面向中国大学 MOOC / SPOC（icourse163.org）的用户脚本（**脚本猫为主渠道**，油猴 / Tampermonkey 同样可用），自动识别两类课程并走对应前端分支，覆盖四大场景：**互评作业自动化、课堂讨论自动回复、随堂测验一键作答、整章自动学习**（视频 / 文档 / 测验 / 讨论全类型自动推进），并提供开发者调试日志与页面结构诊断，便于适配新版 UI。

> 脚本依赖平台 DOM 结构，随慕课新版 UI 持续维护。页面改版后可先用「页面 DOM 诊断」导出结构，反馈给作者精准适配。

## 功能总览

| 模块       | 能力                                                                                |
| -------- | --------------------------------------------------------------------------------- |
| **互评**   | 一键互评 / 快速互评 / 全自动互评 / 评分修复；自动避开测验·作业·考试答题页                                        |
| **讨论**   | 预览回复内容 / 一键回复当前讨论；正文取已有楼层，同一条讨论只回复一次                                              |

| **自动学习** | 从当前内容开始整章自动推进：视频播完→文档翻页→讨论回复→富文本停留；**随堂测验自动作答并提交，提交后停留 10 秒再走**；单元测验 / 作业 / 考试不进入 |
| **课程类型** | 自动识别 MOOC / SPOC 两套前端（导航、题块、题库来源各不相同），互不干扰                                        |
| **日志**   | 开发者调试日志：检测结果、跳转决策、异常捕获，可复制可清空                                                     |
| **工具**   | 页面 DOM 诊断、解除复制限制                                                                  |

### 面板结构

面板是**暗色扁平**风格：纯色底、细边框、只有一个强调色，不放说明文字，只留按钮。

面板按功能分成五个选项卡，同一时刻只显示一个视图：

| 选项卡    | 内容                                                       |
| ------ | -------------------------------------------------------- |
| **学习** | 开始自动学习（当前章）/ 随堂测验一键完成 / 页面 DOM 诊断                        |
| **互评** | 一键互评 / 快速互评 / 全自动互评 / 评分修复                               |
| **讨论** | 预览将回复的内容 / 一键回复当前讨论 / 当前来源                               |
| **日志** | 复制日志 / 清空 / 展开（弹窗看全部，带行号）/ 实时调试日志（时间只到分钟）                |
| **设置** | 讨论内容来源、视频倍速、解除复制限制、清除回复记录、**问题反馈**（一键打开 GitHub 新建 Issue）、**官网**（打开项目站点：功能说明 / 教程 / 更新记录） |

**「学习」排在第一，也是默认打开的选项卡**——自动学习是这个脚本最主要的功能，打开面板就该看到它。

标题栏右上角有一个 **「?」按钮**，点开是完整的使用说明浮层——所有功能的解释都集中在那里：互评、课堂讨论、随堂测验、自动学习、日志与诊断、设置、课程类型。浮层可点右上角 ×、点遮罩空白处或按 Esc 关闭；文案可选中复制。

默认停在「学习」；只有地址栏明确指向讨论详情（hash 里带 `forum` / `discuss` / `topic`）时才自动开「讨论」。只在面板创建时判定一次，之后手动切到哪就留在哪——不跟着单页路由乱跳，免得打断正在进行的操作。

标题栏右上角除了「?」还有一个 **「官网」** 文字入口（`设置` 页签底部也有一个整行按钮），点一下直接打开项目站点 <https://weiy02.github.io/ChinaMOOC-Auto/>，看完整功能说明、图文教程和更新记录。两个入口都是 `<a>`，任务运行期间照样能点。

两处是刻意的设计：

- **状态栏和停止按钮在选项卡之外**，常驻面板底部。任务进度和停止入口不属于任何一个视图，切走就看不到会很糟。
- **任务运行期间可以自由切选项卡**，开关类按钮（解除复制）与日志按钮（复制/清空）也仍可点击——它们和任务状态无关，不该被一起锁住。
- **说明文字一律收进「?」浮层**，面板上不铺大段解释：面板是操作台，不是说明书。

## 课程类型适配（MOOC / SPOC）

平台上有两类课程，前端是两套东西，脚本会先识别课程类型再走对应分支。识别优先看路径（`/spoc/` → SPOC，`/mooc/` → MOOC），路径判断不了才看 DOM（只认 SPOC 独有的 `.up.j-up` 下拉），**宁可漏判 SPOC，也不把 MOOC 带进 SPOC 分支**。

| 维度      | MOOC（新版）                                               | SPOC                                                           |
| ------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| 路径      | `/mooc/learn/{课程}/content/{id}`                        | `/spoc/learn/{课程}/…`                                           |
| 内容项     | `[role="tablist"]` 里的 `[role="tab"]`                   | `.unitslist > .f-fl`（`.current` 为当前项）                          |
| 章节 / 小节 | `header button[aria-expanded]`                         | `.up.j-up`（`[0]` 章、`[1]` 节）+ `.down.j-list` 里的 `.list`         |
| 随堂测验题块  | `LessonQuizUnit` 容器 + `article`                        | `.m-choiceQuestion`                                            |
| 提交 / 重做 | 文字「提交」/「重新答题」                                          | `.j-submit` / `.j-replay`（文字「重做」）                              |
| 题库来源    | `front-mooc-learn/api/…/unit-page` → `result.quizData` | dwr `CourseBean.getLessonUnitLearnVo` → `paper.objectiveQList` |
| 讨论区     | `mooc-comment*` + `contenteditable`                    | `.m-data-lists` / `.f-richEditorText` / `.ql-editor`           |

### 各功能在两类课程下的表现

| 功能       | MOOC           | SPOC                                                               |
| -------- | -------------- | ------------------------------------------------------------------ |
| 互评       | ✅              | ⚠️ 依赖页面列表结构，识别不到会明确提示而不是乱点                                         |
| 讨论自动回复   | ✅              | ✅ 编辑器走 `.ql-editor`，发布按钮走 `.j-edit-btn`，回复正文取自 `.f-richEditorText` |
| 随堂测验一键完成 | ✅ 走接口          | ✅ 走 dwr，取不到时提示切一次标签再试                                              |
| 自动学习     | ✅ tablist + 下拉 | ✅ `.unitslist` + `.up.j-up` 下拉；随堂测验**自动作答**（见下）                    |

### SPOC 的两个特别处理

- **随堂测验不跳过**：两类课程一致——小节里的「测试」就是随堂测验（不限次数、可重做），跳过去没人会回来做，所以自动学习走到它时会自动作答并提交，**提交后停留 10 秒**再进下一个内容。想让随堂测验回到「跳过」的老行为，把 `CONFIG.LEARN_AUTO_QUIZ` 改成 `false`。
- **dwr 答案靠 hook 捕获**：SPOC 的题目和答案在 `getLessonUnitLearnVo.dwr` 的响应里。脚本注入时首屏那条请求已经发完，所以会挂上 dwr 回调 hook 等下一次；还没等到就把当前内容重新点一次逼平台再请求一回。仍失败时会把「请切到别的测试再切回来」写进状态栏——切换一次内容即可让 hook 收到数据。

## 随堂测验一键完成

「自动学习」页签里的**随堂测验：一键完成并提交**，只在**随堂测验**（小节里那个叫「测试」的标签，和视频 / 文档 / 讨论同一层）页面上生效。

它和**单元测验**是两套东西，别混用：

|     | 随堂测验            | 单元测验             |
| --- | --------------- | ---------------- |
| 位置  | 小节内部，与视频 / 文档平级 | 左侧目录里单独一个节点      |
| 次数  | 通常不限次数，可反复重做    | 往往只有一次机会         |
| 本功能 | ✅ 支持            | ❌ 不处理（考试页也会直接拒绝） |

流程：重新答题（若已答过）→ 取正确答案 → 逐题比对填涂 → 点提交 → 处理「确定提交」弹窗。

答案从哪来（两类课程走不同来源）：

| 课程   | 来源                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ |
| MOOC | 课件接口 `front-mooc-learn/api/learn/content/unit-page`，`result.quizData.questions` 每题带 `options[{id,label}]` 与 `correctOptionIds` |
| SPOC | dwr `getLessonUnitLearnVo` 的 `paper.objectiveQList`，选项上直接带 `answer` 标记                                                         |

映射方式（三级，前一级没结果才走下一级）：

1. **平台选项 ID**：页面上 `input` 的 `id` / `name` / `value` / `data-*` 里整段等于答案 ID——最可靠，但页面通常不暴露；
2. **选项文案**：两边都剥掉「A、」「（B）」这类前缀后比对（完全相等 > 互相包含 > 五字滑窗覆盖率 ≥0.8），应对接口不带字母、页面带字母的错位；
3. **字母/顺序**：答案只给了 `correctAnswer="A"` 时，先找选项自带的字母前缀，找不到就按可见顺序定位。

题面匹配同理：题干精确相等 > 互相包含 > 滑窗覆盖率 ≥0.85；题干是图片 / 公式导致文字完全不像时，再按**选项集合重合度**反查（要求选项数 ≥3、重合率 ≥0.8、且唯一最优，判断题刻意不参与，避免张冠李戴）。

> SPOC 下两份答案源（课件接口 / dwr paper）都会试，按「和页面题块对得上几题」择优采用——接口能返回不代表返回的是这套题，之前就是这里把答案认错了。

### 填空题

同样走「题干匹配」，匹配上之后把答案写进空里：

| 环节 | 做法 |
|---|---|
| 认题块 | 有输入框、没选项的容器单独算一题（输入框含 `textarea`、不写 `type` 的 `input`、以及富文本 `contenteditable`） |
| 取答案 | 依次尝试 `correctOptionList` / `correctAnswers` / `answerList` / `answers` / `blankAnswers` / `standardAnswer` / `correctAnswer`——新版 MOOC 接口给的是 `correctOptionList: ["安全机制"]`，老版是 `correctAnswer: "答案#解析"` |
| 填空 | 空数与答案数一致就逐空填，不一致只填第一空；写入后回读校验，没写进去不算完成 |
| 安全约束 | 接口没给答案、空数多于答案数、或某个框没写进去 → **不提交**，状态栏写明还差什么 |

安全约束（和互评、讨论同一套原则）：

- **读不到答案就一个选项都不点、也不提交**——接口没返回 `quizData`、或题目全对不上，直接报错退出；
- **只答对得上的题**：有题目匹配不上时（或接口题数多于页面渲染数，可能分页），只填不交，把状态写清楚留你手动补完，避免交白卷；
- **不等同于 guessing**：判断题、多选题都按接口答案勾选，不猜；
- 只有「确定 / 确认 / 继续」会被点，弹窗里的取消一律不碰。

> 匹配以文案为主、ID 为辅：页面 `input` 的 id 常被平台加前缀（`_102476797525894`），而不同选项的 id 可能互为后缀（`102476797525894` 正好是 `1102476797525894` 的结尾），所以 ID 必须整段相等才认，不能用 `includes`。

## 自动学习（整章自动推进）

在任意内容页点「开始自动学习（当前章）」即可。脚本从当前内容开始处理，学完一个内容自动进入下一个，直到全部章节学完。页面刷新 / 内容跳转后自动续跑，无需手动干预。

### 各类型内容的处理规则

| 内容类型              | 处理方式                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **视频**            | 从头播放（支持倍速），播完自动进入下一个内容；**落点视频若此前已看完，不重播、直接前进**（重播既浪费时间，又会撞上平台“自动播放下一集”）                                                                                       |
| **视频中弹出题目**       | **直接拦截**（默认）：不放行暂停、浮层一出现就收掉，视频一路播到底；拦不住时才自动作答并提交（见下节）                                                                                                         |
| **文档 / 课件 / PPT** | 自动翻页，每页停留约 1 秒，翻到底自动进入下一内容                                                                                                                                    |
| **富文本 / 节标题页**    | 停留 10 秒后自动跳转（可随时点右下角【下一节】提前跳）                                                                                                                                 |
| **随堂测验**          | 自动作答并提交（`LEARN_AUTO_QUIZ` 可关），**提交后停留 10 秒**（`LEARN_QUIZ_AFTER_MS`）再进下一个内容；单元测验 / 作业 / 考试页绝不作答。识别前会先等最多 8 秒让题块渲染出来（`LEARN_QUIZ_READY_WAIT`），不会因为“刚切过来还没渲染”就跳过 |
| **讨论**            | 自动回复（与「讨论」页签同一套逻辑与安全约束）                                                                                                                                       |
| **加载失败页**         | 快速跳过，不停留                                                                                                                                                      |

### 视频弹题是怎么被拦下来的

弹题本质是两件事：**把视频暂停** + **盖一层浮层**。两件事分别掐掉，视频就能一路播下去。

| 手段  | 做法                                               | 为什么这么做                                 |
| --- | ------------------------------------------------ | -------------------------------------- |
| 掐暂停 | 劫持 `HTMLMediaElement.prototype.pause`，弹题那一下不真的执行 | 浮层删了平台会再插，但暂停只发生在打点那一下。那一次没停下来，后面就不会再停 |
| 收浮层 | 主动扫描 + `MutationObserver`，浮层一插进来就 `display:none` | 浮层上通常还压着一层透明遮罩，会把鼠标事件全吃掉，后面脚本要点的按钮就点不动 |
| 补暂停 | 压住 1.2 秒后若没看到浮层，补一次真正的 `pause()`                 | 保证你手点暂停、平台切清晰度这类**正常**暂停不被误伤           |

**风险要说清楚**：这是纯前端拦截。如果平台按「弹题通过数」结算这一段的学习时长，视频播完可能不计进度。验证方法很简单——跑一个带弹题的视频，播完后刷新页面看进度涨没涨。没涨就把「设置」里的**视频弹题拦截**关掉，脚本会退回自动作答并提交（答案优先从课件接口里取，取不到才顺位作答）。

拦不住的情况：浮层如果**包着播放器本身**（`el.contains(video)`），脚本不会去动它——收掉它等于把播放器一起收掉。这种会等 4 秒后转自动作答；连续 5 次还不消失就直接跳过当前视频，避免卡死。

### 跳转逻辑（三级优先级）

跳转一律模拟点击，不直接改 URL，适配新版 SPA 单页应用：

1. **同小节内**：点击当前内容标签的下一个兄弟标签（随堂测验也进，进去自动作答；单元测验 / 考试类标签才跳过）；
2. **跨小节**：当前小节学完，展开顶部「小节」下拉，点击下一节——支持「第X节」分组标题；若点击分组标题后页面无响应，自动改点该节第一个内容单元；
3. **跨章节**：当前小节已是最后一项时，展开顶部「章节」下拉，点击下一章，进入新章节后自动点第一个小节、第一个内容标签。

全部查完没有更多内容时提示「课程学习完成！」。

### 细节

- **视频倍速**：「设置」页签可调 0.5x ~ 3x（步进 0.25）。播放前、播放循环中、弹题恢复后都会持续应用——平台切清晰度 / 拖动进度后可能重置倍速，脚本会自动补回；  
  |  |  |  |  |  
  | --- | --- | --- | --- |
- **类型判定以内容标签为准**：平台给每个内容标签画了图标（`data-lesson-type-icon="pdf|quiz|video|…"`），脚本直接读它判断「这个内容是什么」，而不是看页面上出现了哪个元素。切换标签时旧内容的 DOM 常常还留在页面里（文档查看器尤其明显），只看元素会把测验页判成文档，然后「文档没有翻页按钮」→ 立刻跳走，测验就被这样跳过了；
- **跳转后强制停留 10 秒**：每次跳到新内容后，先硬等满 10 秒（`LEARN_JUMP_SETTLE_MS`）才开始处理。刚切过去时 DOM 往往还是上一份内容（视频元素、题块、正文都还在），立刻判定会认错类型，甚至把还没开始的内容当成已完成而秒跳下一节；等待期间可以点【下一节】提前跳过，点「停止」立即中断；
- **等待期盯住“我在哪个内容上”**（2.1）：跳转时会记下“预期内容”，等待期间每 300ms 校验一次当前激活项。平台的“自动播放下一集”若在这 10 秒里把页面带走（已看完的视频约 5 秒后就会跳到下一个视频），脚本立刻切回预期内容并重新计时，不会任由它把中间的文档/测验/讨论跨过去；落点本身就是已看完的视频时，等待压缩到 1.5 秒（`LEARN_JUMP_SETTLE_FAST_MS`），由脚本按内容条顺序自己前进；
- **加载就绪等待**：进入每个内容先等它真正渲染出来（视频 / 文档查看器 / 讨论页 / 富文本正文任一出现，最长 15 秒），没加载完不跳转，避免“白页秒跳”；
- **【下一节】悬浮按钮**：学习过程中出现在页面右下角，视频 / 文档 / 富文本随时可点，立即进入下一个内容；
- **刷新续跑**：学习计划保存在 localStorage，页面刷新后自动接着跑；点「停止」或手动清掉状态才结束；
- **平台兼容**：开始学习时自动关闭平台自带的“自动播放下一集”，避免与脚本跳转抢节奏。

## 课堂讨论自动回复

脚本不自己编内容，只从**已经有人回复过的楼层**里挑一条现成的答复作为正文。来源可在「设置」里切换：

| 来源           | 说明                                        |
| ------------ | ----------------------------------------- |
| **最新答复**（默认） | 按楼层时间取最新一条；时间解析不出来时退化为页面顺序的最后一条，并在预览里明确写出 |
| **点赞最多**     | 取点赞数最高的楼层；页面没显示点赞数时自动退回「最新答复」并说明原因        |

按下「一键回复当前讨论」之前，建议先点「预览将回复的内容」：浮层会写明选中的是哪一层、点赞数与时间、以及将要发出的正文，确认无误再发。

安全约束：

- **选不出正文就不动手**：解析不到楼层、或楼层正文是占位提示，直接报错退出，不拿任何凑数文本去发
- **同一条讨论只回复一次**：按「讨论标题 + 页面地址」在本地留痕，重复点击会跳过（可在设置里「清除回复记录」）
- **只写回复输入框**：先在「回复区」作用域内找可编辑元素，找不到才看整页——不会把内容写进笔记框、搜索框
- **正文会剔掉作者名 / 时间 / 点赞数**：昵称、楼层时间、点赞条这些元信息节点既不会被当成正文，也会从整层文本里被剥掉（只剥首尾，不动正文中间）。剥完只剩昵称的楼层直接判为无效——宁可报「未解析到」，也不发出「张三」这两个字
- **预览会告诉你作者是谁**：预览里写明「作者「张三」（已从正文剔除）」，方便你核对取的是不是有内容的那一层
- **超长正文截到句子边界**：默认上限 200 字（脚本内 `CONFIG.DISCUSS_MAX_LEN`）
- 找不到发布按钮时，内容会留在输入框里并提示手动发布，不会乱点页面上其它按钮

## 开发者日志

「日志」页签面向**开发者排查问题**（不是给使用者看完成情况）。它记录“检测到了什么、走到了哪一步、为什么这样决策”，每条带时间戳与分类标签：

| 分类                                 | 含义                                                               |
| ---------------------------------- | ---------------------------------------------------------------- |
| `type`                             | 内容类型检测结果与判定依据（video / doc / quiz / discussion / other / missing） |
| `load`                             | 内容加载就绪情况：等了多久、命中哪种正文、是否超时                                        |
| `nav`                              | 三级跳转决策：当前标签是谁、同小节目标、跨小节 / 跨章节目标、tablist 是否刷新成功                   |
| `menu`                             | 下拉菜单：识别到的章节 / 小节按钮、菜单项数量、匹配到谁、下一个是谁                              |
| `learn` / `video` / `doc` / `quiz` | 主流程与各类型处理的关键事件                                                   |
| `err`                              | 异常捕获（含自动学习异常）                                                    |

内存保留最近 500 条，面板展示最近 120 条（自动滚到底部）；「复制日志」导出全部，复制失败时自动改用浮层展示。任务运行中日志按钮依然可用。

**每条日志左侧带行号**（1、2、3…），是「第几条」而不是「本屏第几条」——所以面板滚动到中间、或者弹窗和面板对照着看，都能直接对上。

**「展开」打开日志弹窗**：面板里只有 150px 高、最多 120 条，翻长日志很难受。点日志页签右侧的「展开」，弹出居中的大窗显示全部日志（最多 500 条），同样带行号，可选中复制、可滚动。关闭方式：右上角 ×、点遮罩空白处、按 Esc。弹窗开着时新日志会自动追加，而且**你往上翻的时候不会被拽回底部**——只有原本就在底部才自动跟最新。

## 互评功能

- 自动识别可评阅作业并执行评分
- 默认评语为：`科技改变生活`
- 支持批量处理与延时控制
- 提供停止按钮与评分修复能力
- **自动避开答题页**：在测验 / 作业 / 考试页面上，互评按钮会被拒绝执行（避免把题目选项当作分数选中并提交）

### 解除复制限制

面板「设置」选项卡下的开关。慕课挡复制通常是三套手段，脚本对应三种反制：

| 站点手段                                                                                   | 反制方式                                                                     |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| CSS `user-select: none`（含 JS 写行内样式）                                                    | 注入带 `!important` 的样式表——样式表里的 `!important` 优先于行内样式                        |
| 在 `document` / 元素上挂 `copy`、`cut`、`selectstart`、`contextmenu`、`dragstart` 处理器或 `on*` 属性 | 在 **window 捕获阶段**掐断事件传播。捕获阶段 window 早于 document，站点挂在 document 上的捕获监听也拦不住 |
| 拦截 Ctrl/⌘ + C / X / A 并 `preventDefault`                                               | 同样在 window 捕获阶段掐断（只收窄到这三个组合键，不影响站点自身的快捷键）                                |

关键点是**只掐事件传播、不调用 `preventDefault`**：浏览器的选中、复制、右键菜单等默认行为得以保留，而站点挂的拦截逻辑收不到事件。

开关默认关闭，状态存在本地，刷新后保持。

2. 打开 `main.js`，复制全部脚本内容。
3. 在管理器里新建脚本并粘贴保存（脚本自带 `@match *://www.icourse163.org/*`）。

## 注意事项

- 请仅在你确认允许自动化处理的课程场景中使用。
- 建议先小范围测试，确认课程页面结构正常再批量执行。
- 脚本依赖慕课新版 UI 的 DOM 结构（顶部章节/小节下拉、内容标签栏 `role="tablist"` 等），平台改版后优先用「页面 DOM 诊断」导出结构再反馈问题。
- 视频弹题默认被拦截（不暂停、收浮层）。若平台按弹题通过数结算进度，到「设置」关掉**视频弹题拦截**退回自动作答；两条路都没走通时（浮层包着播放器、或答案始终对不上）才需要手动点一下播放键——浏览器不允许脚本在没有用户手势的情况下恢复播放，这一步绕不过去。
- SPOC 的随堂测验答案来自 dwr 响应，脚本注入时首屏请求已过。若提示「没拿到 dwr 试题数据」，手动切到别的「测试」标签再切回来即可（切换会触发新请求，hook 已在监听了）。
- 互评功能对 SPOC 课程只做页面结构识别，识别不到会直接提示「未检测到互评列表」而不是乱点。
- 自动学习走到随堂测验时，若读不到答案或有题目对不上，**不会提交**，但仍会停留 10 秒后继续下一个内容——状态栏会写明原因，需要的话手动补完再点提交。

## 已知问题

### SPOC 选择题匹配不上（v1.14.4 已针对性加固，仍需实机验证）

**现象**：SPOC 课程的随堂测验里，题块能找到，但出现「有 N 题没匹配上答案」或「一题都没能作答（答案和页面题目对不上）」，选择题几乎全对不上。MOOC 课程不受影响。

**原因分四层**（v1.14.4 逐条处理）：

| 层 | 原来的问题 | 现在的做法 |
|---|---|---|
| 答案解析 | 只认 `optionDtos[].answer === true`，而 dwr 里常是 `"true"` 字符串 / `1`；字段名也可能叫 `optionList` / `isAnswer` / `questionTitle` | 布尔改用真值判定，字段名走优先级表；答案只有字母（`correctAnswer:"A"`）时按选项下标映射 |
| 选项定位 | 按 input 判可见性，SPOC 把原生 radio 设成 `opacity:0` 盖假图标 → 整题选项被丢弃 | 改判 label / 选项容器可见；`label` 之外还认 `li`、`.option`、兄弟节点 |
| 文案比对 | 接口不带「A、」前缀、页面带，或题干里混进了选项文案，归一化后差一大截 | 前缀先剥再比，并加包含关系打分与覆盖率兜底；题干提取改成「删节点 + 按选项文案做字符串减法」 |
| 题块切分 | 选项平铺在一个 `.j-list` 里时，往上爬会把整页题并成一题 | 改按 `name` 分组切题（同题选项共用一个 name），并校验祖先里没有混入别的 name |

**如果还复现**：点「页面 DOM 诊断」，把【随堂测验题块实测】那一段（含每题题干、选项文案、dwr 题量与解析结果）连同日志页签里 `[quiz]` 开头的「对照诊断」一行一起反馈。这两段能直接区分是「题块切错了」「题干对不上」还是「选项对不上」——比截半张源码图有用一百倍。

### 测验页被跳过：标签说 quiz、页面没题（v1.14.5 已修，待实机验证）

**现象**（典型日志）：

```
[load] 按当前内容标签类型等待：quiz
[load] ⚠️ 内容加载超时（15000ms 内未见任何正文）（标签类型=quiz）
[quiz] 等了 8000ms 仍未识别到随堂测验容器/题块
[learn] quiz：……（单元测验/作业/考试页），不作答，跳过
```

**原因**：标签明确说是 `quiz`，页面里却一块题都没有——旧实现只会**干等 23 秒，然后当成单元测验跳过**。这种页面其实有三种状态，旧代码对三种的处理都是「等」，等于放弃：

| 页面真实状态 | 旧行为 | v1.14.5 |
|---|---|---|
| 停在「已提交/查看解析」结果态（没有作答区，但有「重做」按钮） | 没题块 → 判成单元测验 → 跳过 | 先点「重做」回到作答态再作答 |
| 标签切了、内容区没回填（XHR 失败 / SPA 状态没刷新） | 白等 23 秒 → 跳过 | 重按当前标签最多 2 轮；还等不到就「切到相邻内容再切回」，逼平台重新请求 |
| 课件本身坏了（unitId/lessonId 不匹配） | 白等 23 秒 → 跳过 | 认出「课件不存在/加载失败」直接跳过，不浪费 50 秒 |

顺带修的两个判定漏洞：

- **题块检测不再只认类名**：当前标签类型是 `quiz`、且页面里真有 ≥2 个可见单选/多选框时也算题块，修「标签=quiz、题块类名不认识 → 等满 15 秒判超时」；加标签类型这个门槛，不会在视频弹题浮层、讨论区上误判。
- **白页不再默默判加载失败**：视频 / 文档 / 讨论超时未渲染时，先重按一次当前标签催重载（8 秒），失败才按类型继续或跳过——这条修的是「视频/课件还没渲染就被跳过」。

放弃作答时日志会给一份**现场摘要**：`标签类型`、`可见单选框数`、`题块类名是否命中`、`是否有「开始答题/查看测验」入口按钮`、`页面是否提示课件不存在或停在结果态`。下次再遇到「跳过」，看这一行就知道是哪一类。

> 若摘要里出现「入口按钮[开始答题]」之类，说明那确实是**单元测验/作业的入口页**，脚本按设计不进去（只有一次机会），这不是 bug。

### 自动学习时会跳过随堂测验（旧问题，1.14.0~1.14.1 的判定逻辑遗留）

**现象**：用「开始自动学习」跑到随堂测验那一节时，脚本仍可能把它识别成别的内容类型（例如文档）而直接跳到下一个内容，测验不会被作答。**同一个页面改用「随堂测验：一键完成并提交」按钮手动点，可以正常作答并提交。**


**影响范围**：只影响「自动学习」这条路径；手动按钮、互评、讨论、日志等功能不受影响。

**已做过的尝试**（都没能彻底解决）：

| 版本 | 尝试 | 结果 |
|---|---|---|
| 1.12.0 | 导航层不再跳过「测试」标签 | 能进到测验页，但进去后可能被认成别的类型 |
| 1.14.0 | 与手动按钮统一判据（容器 + 题块），判定前给 8 秒等待窗口 | 部分场景修好，仍有复现 |
| 1.14.1 | 类型判定改为以内容标签的 `data-lesson-type-icon` 为准 | 修复「残留文档查看器把测验判成文档」，仍有复现 |

**当前判断**：手动能过、自动不能过，说明差异出在「自动学习判定类型」这一步，而不是作答逻辑本身。剩余可能原因：

- 跳转后内容标签尚未更新为 `aria-selected="true"`，`currentContentTab()` 取到的是上一个标签；
- 该测验所在的标签没有 `data-lesson-type-icon`，且题块容器类名不在已知列表里；
- 测验内容渲染时间超过「强制停留 10 秒 + 就绪等待 15 秒」；
- 内容不在小节内容条里（例如独立页），被安全策略判成单元测验而拒绝作答。

**临时规避**：自动学习跳到该测验页后，停下来手动点「随堂测验：一键完成并提交」。

**排查需要的信息**：日志页签里 `[type]` / `[load]` / `[quiz]` 这三类行，以及跳转前后两个内容标签的 `outerHTML`（含 `role="tab"` 与 `data-lesson-type-icon`）。
