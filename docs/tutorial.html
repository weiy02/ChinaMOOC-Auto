01安装脚本

脚本本身只是一段 JS，需要一个「脚本管理器」扩展来承载。装哪个都行，功能完全一致。

  1. 装管理器

    Chrome / Edge 装 Tampermonkey，或装 脚本猫（国内访问更稳）。装完记得在扩展管理里把「允许运行用户脚本」打开。

  2. 点一下安装

    打开 Greasy Fork 或 脚本猫 的脚本页，点「安装此脚本」，管理器弹出确认界面时点「安装」。

  3. 打开慕课页面验证

    进入 icourse163.org 任意学习页，右侧应该浮出面板。看不到就是没生效——先确认脚本已启用、地址匹配 *://www.icourse163.org/*，再刷新页面。

手动装也行：打开 main.js 复制全文，在管理器里新建脚本粘贴保存。缺点是以后不会自动更新。

02认识面板

面板是暗色扁平的一块操作台，五个选项卡，一次只显示一个视图。标题栏右上角那个「?」点开是完整说明浮层——所有解释都在里面，面板上只留按钮。

选项卡干什么
学习开始自动学习、随堂测验一键完成、页面 DOM 诊断（默认打开的就是它）
互评一键 / 快速 / 全自动互评、评分修复
讨论预览回复内容、一键回复当前讨论
日志开发者日志，复制 / 清空 / 展开大窗
设置讨论来源、视频倍速、弹题拦截、解除复制、问题反馈、官网

底部那条状态栏和「停止」按钮在选项卡之外常驻——任务跑起来之后你切到哪个页签都能看到进度、都能随时喊停。

03互评作业

进到互评列表页，切「互评」页签，按需要点：

  • 一键互评——评当前这一份，一步步走完再停下，适合先试一份；
  • 快速互评——省掉多余等待，节奏更快；
  • 全自动互评——连续处理一批，默认批数 10 份，随时可停；
  • 评分修复——发现某份没评上 / 评错，用它重跑一遍。

评分时脚本会解析每档分的真实分值，选最高分那一档，评语默认「科技改变生活」。在测验、作业、考试答题页上，互评按钮会被主动拒绝——那是防止把题目选项当分数点掉。

04课堂讨论自动回复

脚本不编内容，只从已经有人回复过的楼层里挑一条现成答复来发。所以正确姿势是：先预览，再发送。

  1. 切到「讨论」页签，点「预览将回复的内容」——浮层会写清楚选中的是哪一层、作者是谁、点赞数和时间，以及即将发出的正文。
  2. 确认没问题，再点「一键回复当前讨论」。同一条讨论只回复一次，脚本会在本地留痕，重复点会跳过。

正文来源可在「设置」里切：最新答复（默认）或点赞最多。超长正文会截到句子边界，默认上限 200 字；昵称、时间、点赞数这些元信息会被剥掉，剥完只剩昵称的楼层直接判无效。

05随堂测验一键完成

先分清楚这两个东西，混用会出事：

随堂测验单元测验
位置小节内部，与视频 / 文档平级左侧目录里单独一个节点
次数通常不限次数，可反复重做往往只有一次机会
脚本会作答并提交不处理，答题页直接拒绝

在随堂测验页面上，点「学习」页签里的「随堂测验：一键完成并提交」，流程是：重新答题（若已答过）→ 取正确答案 → 逐题比对填涂 → 提交 → 处理确认弹窗。

答案来源：MOOC 走课件接口，SPOC 走 dwr 响应。安全约束很硬——读不到答案就一个选项都不点、也不提交；有题目对不上时只填不交，把状态写清楚留你手动补完，绝不交白卷。

选项是怎么对上的

「匹配不上」几乎都出在这一步，所以脚本按三级来找，前一级没结果才走下一级：

  • 平台选项 ID——input 的 id/name/data-* 里整段等于答案 ID。最可靠，但页面往往不暴露。
  • 选项文案——两边都剥掉「A、」「（B）」这类前缀再比：完全相等 > 互相包含 > 五字滑窗覆盖率 ≥ 0.8。专门对付「接口不带字母、页面带字母」。
  • 字母 / 顺序——答案只给了 correctAnswer:"A" 时，先找选项自带的字母前缀，找不到就按可见顺序定位。

题干同理：精确相等 > 互相包含 > 覆盖率 ≥ 0.85；题干是图片或公式、文字完全不像时，再按选项集合重合度反查（要求选项数 ≥ 3、重合率 ≥ 0.8、且唯一最优——判断题刻意不参与，避免张冠李戴）。SPOC 下课件接口和 dwr 两份来源都会试，按「和页面题块对得上几题」择优采用。

还是对不上？「学习」页签 →「页面 DOM 诊断」，找里面的【随堂测验题块实测】：每题题干、选项文案、dwr 题量与解析结果都在那段里，还附了题块的原始 HTML。把这段连同日志里 [quiz] 对照诊断 那行发出来，是题干的问题还是选项的问题一眼就清楚。

06整章自动学习

这是脚本的主功能。进任意内容页，点「开始自动学习（当前章）」，脚本从这个内容开始，一路往后推：视频播完 → 文档翻页 → 讨论回复 → 随堂测验作答，跨小节、跨章节自动走，直到本章学完。

它怎么处理各类内容

类型行为
视频从头播放（可倍速），播完进入下一个内容；打开时已看完的视频不重播，直接前进
视频中弹题默认直接拦截：不暂停、收浮层，一路播到底；拦不住才自动作答
文档 / 课件 / PPT自动翻页，每页约 1 秒，翻完进下一个
富文本 / 节标题停留 10 秒后跳转，可点右下角【下一节】提前跳
随堂测验自动作答并提交，停留 10 秒再走；题块没渲染出来会自救（重做 / 重开 / 重载）而不是跳过
讨论自动回复，与「讨论」页签同一套逻辑
白页 / 内容没渲染先重按当前标签催一次重载（8 秒），仍不行才按类型继续或跳过
加载失败页课件真的坏了（提示课件不存在 / unitId 不匹配）则快速跳过，不空等

几个值得知道的机制

  • 右下角【下一节】——学习过程中随时出现，嫌某段内容墨迹，点它直接进下一个。
  • 刷新续跑——中断了不用从头来，刷新页面脚本会接着上次的进度跑；计划存在本地，点「停止」才结束。
  • 跳转后强制停留 10 秒——刚切过去时页面往往还是上一份内容，立刻判定会认错类型、甚至把没开始的内容当已完成。这 10 秒里你可以点【下一节】跳过。
  • 按内容条逐项前进——同小节的「下一个内容」取自内容条的完整顺序（索引 +1），不是找当前标签的相邻节点。标签被容器包住、或视频 / 文档 / 测验 / 讨论交替出现时，顺序都不会乱，也不会漏项。
  • 等待期盯住位置——跳转时记住「我该在哪个内容上」，这 10 秒里持续校验。平台的「自动播放下一集」若把页面带走了（已看完的视频约 5 秒后就会跳），脚本立刻切回原内容并重新计时，不顺着平台跳过中间的文档 / 测验 / 讨论。
  • 测验页自救——标签写着「测验」但题块没出现时，脚本会依次尝试：点「重做」回作答态 → 点「开始答题」入口 → 重按当前标签 → 切到相邻内容再切回。全都失败才跳过，并在日志里留下一行现场摘要（标签类型 / 可见单选框数 / 入口按钮 / 是否结果态）。
关于视频弹题的一个重要提醒：

默认策略是把弹题「拦」掉——不放行暂停、浮层一出现就收。这是纯前端拦截，如果平台按「弹题通过数」结算这一段学习时长，视频播完可能不计进度。

验证方法：跑一个带弹题的视频，播完后刷新页面看进度涨没涨。没涨就到「设置」里关掉视频弹题拦截，脚本会退回自动作答并提交。

07设置项

设置说明
讨论内容来源最新答复 / 点赞最多
视频倍速0.5x ~ 3x，步进 0.25；平台切清晰度重置后脚本会自动补回
视频弹题拦截默认开；进度不计时关掉它，退回自动作答
解除复制限制默认关；开了能复制课件文字，只掐站点的事件拦截，不动浏览器默认行为
清除回复记录清掉「哪条讨论已回复过」的本地记录
问题反馈一键打开 GitHub 新建 Issue
官网打开功能说明、图文教程与更新记录（标题栏右上角也有一个「官网」）

08出问题了怎么办

按这个顺序走，比反复点按钮有用得多：

  1. 先看状态栏

    脚本拒绝执行时会写清原因（「未检测到互评列表」「没拿到 dwr 试题数据」…）。绝大多数情况状态栏已经告诉你答案了。

  2. 再导 DOM 诊断

    「学习」页签 →「页面 DOM 诊断」，导出的结构能让作者快速判断是不是平台改版。

  3. 最后看日志

    「日志」页签记录检测结果、跳转决策、异常，带连续行号。点「展开」能看全部（最多 500 条），复制出来就够提 Issue 用了。

提 Issue 时附上这两样：DOM 诊断导出 + 日志里 [type] / [load] / [nav] 三类行。有这两样，改版适配基本一轮就能修完。

测验相关的两类专项排查

测验出问题，先分清是「没作答」还是「答了但不对」，两条路要看的东西完全不同：

  • 测验被跳过、没作答——看日志里 [quiz] 的现场摘要：标签类型、可见单选框数、题块类名是否命中、有没有「开始答题」入口、是否停在结果态。若摘要显示「入口按钮[开始答题]」而脚本没进，说明它判断那可能是单元测验入口（只有一次机会，按设计不碰）。
  • 作答了但选项不对 / 一题都没勾上——看日志里 [quiz] 对照诊断 那行（页面题块与答案逐条对照），以及 DOM 诊断里的【随堂测验题块实测】：前者看题干对不对得上，后者看选项文案与答案解析结果。
别急着反复点按钮：随堂测验可以重做，但单元测验往往只有一次机会。判断不了是哪一种时，看日志里的标签类型——quiz 且在小节内容条里才是随堂测验。
